v2.0.1-2610.2221  v2.0.1 -- Herald's own configuration names; a time limit for a message on ActiveMQ
    :Config:      the bus configuration is read under herald (was esquire): the shared topology at
                  herald.messaging-bus, a service's bus at herald.<key>.messaging-bus
    :Config:      the keep's meters and trace are named herald.keep.*; the default Kafka consumer group
                  is herald-xxrod-audit
    :Feature:     an ActiveMQ leg can set how long a message may wait for a consumer (timeToLiveMs);
                  after that the broker drops it
    :Doc:         doc\Herald.MessagingBus.md
                  doc\Herald.MessagingBus.Guides.md

v2.0.0-2610.1419  v2.0.0 -- the first release: the messaging framework leaves Esquire
    :Refactoring: herald-messaging, the framework, comes from Esquire services, where it was
                  messaging
    :Refactoring: herald-dataKeep, the keep that writes bus messages into a database, comes from
                  Esquire services; it no longer depends on the Esquire common library
    :Refactoring: the transports come from Esquire services: herald-tp-activemq, herald-tp-kafka,
                  herald-tp-redis, herald-tp-sqns, herald-tp-kinesis
